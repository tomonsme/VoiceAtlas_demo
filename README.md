# VoiceAtlas Docker Web App

VoiceAtlasの初期プロトタイプです。ログイン、初回同意、ライト登録、ホーム画面、プロフィール編集、研究参加同意、氏名・住所登録、研究認証バッジ表示、同意履歴の確認までを、Docker上のWebアプリ + PostgreSQLで動かせます。

本番はAWS（認証はAmazon Cognito、DBはRDS、実行基盤はコンテナオーケストレーション）を想定しており、このリポジトリは**機能とフローを説明するためのモック**です。

## 画面フロー

```
ログイン / アカウント作成      ← 本番は Cognito
  ↓
利用規約・プライバシー同意
  ↓
ライト登録（ニックネーム・疾患・状態・年代・性別）
  ↓
本日の記録 ─┬─ 今日の記録（体調・疲労感・睡眠・労作後の悪化）
            └─ この30日の推移

マイページ ─┬─ プロフィール（編集）
            ├─ 登録状況 → 同意履歴 / 研究参加
            ├─ 通知（拡張予定）
            └─ アプリとして使う（インストール導線）

研究 ─── 研究の一覧（参加している / 募集中 / その他）
        └─ 研究の詳細
            ・未参加なら内容を確認して参加（同意 → 氏名・住所 → 研究認証バッジ）
            ・参加中なら検体トラッキング
                ・検体・データの利用目的（工程タップでモーダル）
                ・撤回できる範囲の区切り（フロー内の破線）
```

タブは **本日の記録 / 検索 / 研究 / 交流 / マイページ** の5つで、ログイン後は本日の記録に着地します。マイページはアカウント情報だけを扱い、日々の記録とは分けています。

タブの画面は見出しを表示しません（サイドバーが現在地を示すため）。支援技術向けには非表示の見出しを置いています。タブにない画面（プロフィール編集、同意履歴など）には見出しを表示します。

セッションはCookieで保持されるため、リロードしても続きから再開できます。ログアウトはサイドバー（モバイルはヘッダー）から行います。

## 毎日の記録

マイページの主役は日々の記録です。続けられる短さと、あとから分析できる形の両立を狙っています。

**入力は3項目＋2つの任意欄。**体調（必須）、疲労感、睡眠を5段階から選び、「動いた後に症状が悪化した」のチェックとひとことを任意で添えます。体調だけ選んで保存もできます。

**すべての尺度は 1 = 最も悪い 〜 5 = 最も良い で揃えています。**疲労感も「5 = 疲労がない」と表現し、列ごとに向きが変わらないようにしています。集計時に項目ごとの反転処理が不要になります。

日付はサーバ側で決めます（`current_date`）。クライアントから日付を受け取ると、日々の記録であるはずのものに任意の過去を書き込めてしまうためです。1日1件で、同じ日は上書きされます。

### 推移グラフ

直近30日を1日1本の棒で表示します。折れ線ではなく棒なのは、記録のない日があるためです。折れ線は空白を直線でつないでしまい、無いデータをあるように見せます。未記録の日は淡い空欄として描き、「悪い日」と区別しています。

色は1色です。棒の高さがすでに値を表しているため、色に同じ情報を持たせていません。2色目は「労作後の悪化」だけに使っています（高さでは表せないため）。配色は `dataviz` の検証スクリプトにかけ、明度帯・コントラスト・色覚特性下での分離を確認しています。

### 同じ疾患との比較

同じ疾患を記録している人の平均を表示しますが、**5人分たまるまでは伏せます**。希少疾患で数人しかいない状態の「平均」は、個人を名指しするのに近いためです。人数が足りない場合はその旨を表示します。

デモでは筋痛性脳脊髄炎に6人分の記録があるため、ティッピーとゆきでは平均が表示され、他のアカウントではしきい値の説明が表示されます。

## PWA

ホーム画面に追加して、ブラウザのバーがない状態で使えます。ネイティブアプリを別途作らずにAndroid / iOSへ配布する前提の構成です。

- `app/public/manifest.webmanifest` — 表示モード、テーマ色、アイコン（192 / 512 / maskable）
- `app/public/sw.js` — Service Worker
- `app/public/icons/` — アイコン。ロゴのマークから生成しています

画面ごとにURLを持つため、ブラウザの戻る／進むとiOSのスワイプバックが機能します。インストール済みの状態ではブラウザの戻るボタンが出ないので、この対応がないと前の画面に戻れなくなります。

Androidはインストールプロンプトを出し、iOSは共有ボタンからの手順をマイページに案内します（一度閉じると再表示しません）。

### キャッシュの方針

**キャッシュするのはアプリシェル（HTML / CSS / JS / アイコン）だけで、`/api/*` のレスポンスは一切保存しません。**

Cache Storageは端末のディスクに残り、ログアウトしても消えません。病歴や氏名・住所をキャッシュすると、共有端末や紛失端末から後から読み出せてしまいます。オフラインで利用者データを見せる要件が出た場合は、ログアウト時の消去処理とセットで実装してください。この方針は `sw.js` の冒頭にも記載しています。

取得方式はネットワーク優先で、キャッシュはオフライン時のフォールバックとしてのみ使います。開発中に古いビルドが表示されることはありません。

### 未対応（配信時に実施）

パスキー（WebAuthn）とドメイン設計。パスキーはPWAでも問題なく使えますが、認証をCognitoに置き換える段階で扱います。Cognito Hosted UIを既定ドメインのまま使うとパスキーがAWSのドメインに紐づくため、カスタムドメインの割り当てを先に決める必要があります。

プッシュ通知も未実装です。iOSではホーム画面に追加した場合のみ動作します。

## 起動

```bash
cp .env.example .env
# .env の POSTGRES_PASSWORD / DATABASE_URL / BASIC_AUTH_PASSWORD を必ず書き換える
docker compose up --build
```

ブラウザで `http://localhost:3000` を開きます。ポートは `127.0.0.1` にのみ束縛され、トンネルも起動しないため、外部からは見えません。

ローカルで使う分にはBasic認証は不要なので、`.env` は `BASIC_AUTH_ENABLED=false` を既定にしています。ブラウザの認証ダイアログは出ません。外部に公開するときだけ `true` にしてください（[限定テスト公開](#限定テスト公開)）。

依存パッケージは `package-lock.json` に固定され、ビルド時に `npm ci` で再現可能にインストールされます。

## デモ用アカウント

ログイン画面にボタンとして並んでいます。パスワードは何でも通ります（モックのため検証していません）。

| メールアドレス | 状態 |
| --- | --- |
| `tippy@example.jp` | ライト登録・研究参加ずみ。規約は 1.0.0 → 1.1.0 の再同意履歴あり。検体は解析からデータベース登録まで完了 |

新規サインアップの流れを見せる場合は、任意のメールアドレスで「アカウント作成」を使ってください。募集中の研究に参加すれば、検体が発送された直後の状態（まだ全面撤回できる段階）から追えます。

同じ疾患の平均は記録した人が5人に達するまで伏せる設計のため、デモ用アカウントが1件の間は常に「5人分たまると表示します」の状態になります。

## 研究ページ

研究タブは**研究の一覧**から始まります。参加している研究、募集中の研究、その他（終了など）に分かれ、カードごとに実施機関・対象・状態を表示します。参加中の研究には参加日と検体の進捗（8工程中いくつ）も出ます。

カードを開くと**研究の詳細**です。未参加の研究でも内容と利用目的を確認でき、募集中ならそこから参加できます。参加・撤回はいずれも対象の研究を明示して行うため、複数の研究に同時に参加できます。

参加中の研究の詳細では、以下を表示します。撤回済みのユーザーも閲覧できます。

**検体トラッキング** — 採取キット発送から研究データベース登録までの8工程を、日付・場所つきのタイムラインで表示します。研究参加を完了した時点でキットが発送された状態になります。

**検体・データの利用目的** — 目的ごとに「使用するもの」「提供先」「保管期間」「撤回で止められるか」を表示します。内容は `study_data_uses` テーブルのデータで、UIに直接書いていません。研究ごとに差し替えられます。

**撤回できる範囲** — 専用のセクションは設けず、タイムライン上の破線で区切っています。撤回できる範囲は検体の進捗で変わります。

| 段階 | 撤回できる範囲 |
| --- | --- |
| 解析開始前 | 全面撤回。検体を破棄し、提供情報をすべて削除 |
| 解析開始後 | 検体の破棄と以後の利用停止は可能。解析済みデータは削除できない場合がある |
| データ固定日以降 | 以後の利用停止のみ。統計処理に含まれたデータは取り出せない |

期限は「解析開始予定日」と「データ固定日（`research_studies.data_lock_at`）」の2本の破線として、フローの中に残日数つきで表示します。撤回操作そのものはページ最下部の目立たないリンク（既定は折りたたみ）に置いています。

デモ中に段階の変化を見せるため、検体を次の工程へ進めるボタンを置いています。実際には検査機関側のシステムが更新する操作です。`.env` に `DEMO_CONTROLS=false` を設定すると非表示になります。

## Netlify で公開する

**そのまま繋ぐだけで公開できます。ビルドもデータベースも要りません。**

Netlify にこのリポジトリを接続すれば、`netlify.toml` の設定（`app/public` を配信）で動きます。環境変数も不要です。

### 仕組み

画面のサーバ通信は `app/public/js/api.js` の1箇所に集約されています。静的配信では `/api/*` が SPA のHTMLに落ちるため、**最初の1回でJSONが返らないことを検知して、以降はブラウザ内のモック（`js/mock-api.js`）が応答します**。設定の切り替えは不要で、docker compose で起動したときは自動的に本物のAPIを使います。

モックは本物と同じ応答の形を返すので、画面側のコードは共通です。カバーしている範囲:

- ログイン、サインアップ、ログアウト
- 本日の記録（1タップ記録、詳細入力、修正）と30日／90日の推移
- 研究の一覧・詳細、検体トラッキング、工程送り、参加、撤回
- プロフィール編集、同意履歴

記録や工程送りなどの操作は `localStorage` に残るため、デモ中に触った結果はリロードしても消えません。ブラウザのデータを消せば初期状態に戻ります。

グラフの日付は常に「今日」からの相対で生成しているので、時間が経っても表示がずれません。

### 制約

- **データはブラウザごとに独立**です。別の端末で開けば初期状態から始まります
- 同じ疾患の平均は、記録者が自分ひとりなので常に「5人分たまると表示します」の状態です
- ログインは `tippy@example.jp` のみ受け付けます（パスワードは任意）

### 実データベースを繋ぐ場合

Netlify Functions 用の入口（`netlify/functions/api.js`）と依存（ルートの `package.json`）は残してあります。外部の PostgreSQL を用意したうえで `netlify.toml` に以下を足し、環境変数（`DATABASE_URL` / `DATABASE_SSL=true` / `BASIC_AUTH_ENABLED=true` とその資格情報 / `PG_POOL_MAX=1`）を設定すれば、本物のバックエンドで動きます。

```toml
[build]
  command = "npm install"
  functions = "netlify/functions"

[functions]
  node_bundler = "esbuild"
  included_files = ["db/init/**"]

[[redirects]]
  from = "/api/*"
  to = "/.netlify/functions/api/api/:splat"
  status = 200
  force = true
```

`BASIC_AUTH_ENABLED` を `true` にしないと全リクエストが503になります（ローカル以外からのアクセスを拒否する安全装置のため）。

## 限定テスト公開

Cloudflare Quick Tunnelで一時公開できます。起動するたびにランダムな `trycloudflare.com` URLを発行するため、短時間の確認・デモ用途です。

トンネルはプロファイル指定でのみ起動します。`docker compose up` では立ち上がらないので、ローカル確認中に誤って外部公開されることはありません。

```bash
# .env で BASIC_AUTH_ENABLED=true にしてから
docker compose --profile tunnel up -d
docker compose logs -f cloudflared   # 発行されたURLを確認
```

Basic認証はアプリ全体にかかります。`.env` に以下を設定してください。

**`BASIC_AUTH_ENABLED=false` のままトンネルを開いても情報は出ません。**アプリはリクエストのHostと転送ヘッダーを見て、ローカル以外からのアクセスを503で拒否します。認証を切ったまま公開されることは構造的に起きません。

```env
BASIC_AUTH_ENABLED=true
BASIC_AUTH_USERNAME=<任意のユーザー名>
BASIC_AUTH_PASSWORD=<十分に長いランダム文字列>
BASIC_AUTH_REALM=VoiceAtlas Test
```

パスワードの生成例:

```bash
openssl rand -base64 24
```

起動:

```bash
docker compose up --build
```

発行された外部公開URLは `cloudflared` のログに出ます。

```bash
docker compose logs -f cloudflared
```

Quick Tunnelでは `TUNNEL_TOKEN` は使いません。Named Tunnelへ戻す場合だけ使用します。

## DB設定

接続情報は `.env` にのみ置きます。**このREADMEを含め、パスワードをリポジトリ内のファイルに書かないでください。**
`POSTGRES_PASSWORD` と `DATABASE_URL` は既定値を持たず、未設定なら `docker compose` が起動を拒否します。

ローカルPCからDBへ接続する場合:

```text
Host: localhost
Port: 5432          # .env の DB_PORT
Database: voiceatlas
User: voiceatlas
Password: .env の POSTGRES_PASSWORD を参照
URL: postgresql://<POSTGRES_USER>:<POSTGRES_PASSWORD>@localhost:5432/<POSTGRES_DB>
```

アプリコンテナ内から接続する場合はホスト名が `db` になります（`.env` の `DATABASE_URL` がこの形式です）。

```text
URL: postgresql://<POSTGRES_USER>:<POSTGRES_PASSWORD>@db:5432/<POSTGRES_DB>
```

現在の値を確認するには、リポジトリにコミットされない `.env` を直接参照してください。

```bash
grep -E '^(POSTGRES_|DATABASE_URL)' .env
```

## DB初期化

`db/init/` の3ファイルが実行されます。

- `001_schema.sql`: テーブル定義
- `002_seed.sql`: 同意文書、疾患マスタ、研究プロジェクト、利用目的、バッジ
- `003_demo_users.sql`: デモ用アカウント1件と、その検体・取り扱い履歴、直近200日ぶんの記録（約83%の日を埋め、残りは未記録）

PostgreSQLがこれらを実行するのは空ボリュームの初回起動時だけなので、**アプリの起動時にも同じ3ファイルを再適用**しています。すべて再実行しても安全に書かれているため、テーブルやデモアカウントを追加しても `docker compose down -v` なしで反映されます。本番ではこの仕組みをマイグレーションツールに置き換えます。

デモアカウントだけを初期状態に戻す場合（登録内容や研究参加の履歴をリセットする）:

```bash
docker compose exec db psql -U voiceatlas -d voiceatlas -c "delete from users where email like '%@example.jp';"
docker compose restart app
```

DBをまっさらにして初期化し直す場合:

```bash
docker compose down -v
docker compose up --build
```

> **警告:** `-v` はDBボリュームを削除します。登録済みユーザー、同意履歴、研究用本人情報がすべて消え、
> 現時点でバックアップの仕組みはないため復旧できません。通常の停止は `docker compose down`（`-v` なし）を使ってください。

## 主なテーブル

- `users`: アカウント本体。サインアップで作成。`email` はログイン識別子（本番はCognitoのサブジェクトのミラー）。
- `user_sessions`: ログインセッション。Cookieにはランダムなトークンを入れ、DBにはそのハッシュのみ保存。
- `consent_documents`: 利用規約、プライバシー、研究同意の文書バージョン。
- `user_consents`: ユーザーごとの同意・撤回履歴。
- `diseases`: 疾患マスタ。
- `user_conditions`: 疾患、状態、ステージ、治療状況。
- `daily_checkins`: 1日1件の記録。体調・疲労感・睡眠（各1〜5）、労作後の悪化、ひとこと。
- `user_demographics`: 年代、性別など任意属性。
- `research_studies`: 研究プロジェクト。
- `research_enrollments`: 研究参加登録と認証状態。
- `research_identity_profiles`: 研究用の氏名・住所。通常プロフィールとは分離。
- `study_data_uses`: 研究ごとの利用目的・使用する項目・提供先・保管期間。参加者にそのまま表示。
- `specimens` / `specimen_events`: 検体1件と、その取り扱い履歴（トラッキングの表示元）。
- `badges` / `user_badges`: 研究認証バッジなど。
- `social_profiles`, `user_follows`, `communities`, `posts`: 将来の検索・SNS・コミュニティ拡張用。
- `reports`, `moderation_actions`, `audit_logs`: 通報、運営対応、監査ログ。

## 実装メモ

### 認証・認可

ログインはサーバ側のCookieセッションで、パスワードは保存も検証もしていません（モックのため）。本番ではAmazon Cognitoに置き換えます。

置き換えても残る部分として、**すべてのAPIはユーザーIDをセッションから取得し、リクエストのbodyやパスからは受け取りません**。他人のIDを指定して他人のデータを読み書きすることはできず、この形は本番でもそのまま使えます。Cognitoが担うのは認証（誰であるか）までで、認可（そのデータを触ってよいか）はアプリ側の責務です。

### 検体トラッキングと撤回期限

工程の定義と「いま何が撤回できるか」の判定は [`app/src/research.js`](app/src/research.js) にまとめ、APIが組み立てた結果をフロントに渡しています。フロント側に工程リストを持たせていないため、定義がずれることはありません。

判定の基準は2つです。**解析の開始**が検体にとっての後戻りできない地点で、**データ固定日**がそこから得られた結果にとっての後戻りできない地点です。

### 日本語・英語の切り替え

画面右下（スマホはヘッダ）の切り替えで、日本語と英語を行き来できます。選んだ言語は `localStorage` に残り、初回は端末の言語設定から推定します。

分け方は次の2つです。

- **UIの文言（chrome）** は [`app/public/js/i18n.js`](app/public/js/i18n.js) の辞書に `t("nav.today")` の形で持ちます。ja / en の両方に同じキーが揃っている必要があります。
- **内容（content）** ── 研究名、概要、利用目的の本文など ── はデータ側が `{ ja: "…", en: "…" }` の形で持ち、`pick()` で取り出します。研究が増えるたびに辞書を触らずに済むためです。

サーバやモックが返す文言（工程名、撤回可能範囲の説明、研究のステータス）は、**表示のたびにコードから引き直します**（[`app/public/js/labels.js`](app/public/js/labels.js)）。サーバが返した日本語をそのまま出すと、言語を切り替えても日本語のままになるためです。辞書にキーがない値（本番DBの自由記述など）だけ、サーバの文字列をそのまま使います。

疾患・年代・性別は**保存される値を日本語のまま固定**し、表示だけ `optLabel()` で訳しています。言語を切り替えても保存済みのデータの意味が変わらないようにするためです。

日付も言語に合わせて綴ります（`2026年3月31日` / `31 March 2026`）。

### 本番化で追加が必要なもの

研究用個人情報の暗号化、バックアップ、監査ログの保全、同意文書の法務確認、退会とデータ削除の導線、研究参加の中間ステータス（申請中→本人確認→認証）、検査機関システムとの連携（現在は工程送りが手動のデモ操作）。

現在は研究同意を撤回しても `research_identity_profiles` の氏名・住所は残ります。撤回時に検体は破棄・記録されますが、氏名・住所の扱いは同意文書の記載と実装を一致させる必要があります。

氏名・住所は `research_identity_profiles` に分離しており、通常のプロフィール、検索、SNS機能では参照しない前提です。
